Batch Content Generation System

Product & Technical Specification

Project Goal

Implement a Batch Content Generation System within the existing React Flow (XYFlow) workflow builder.

The goal is to allow a user to upload a single video and automatically generate dozens of content variations without cluttering the workflow canvas.

This is not a feature that creates 30 visual nodes. Instead, it introduces a Collection data type that allows one node to internally process multiple outputs.

⸻

Core Concept

Instead of:

Video
 ├─ Video 1
 ├─ Video 2
 ├─ Video 3
 ...
 └─ Video 30

The workflow should behave like:

Video
    │
Batch Generator
    │
Collection<Video>
    │
Caption Generator
    │
Thumbnail Generator
    │
Publisher

Only one Batch Generator node exists on the canvas.

Internally, that node creates multiple execution jobs.

⸻

User Experience

The user should be able to:

* Upload one video.
* Choose how many variations to generate.
* Keep the original editing style.
* Select output platform.
* Execute the workflow.
* View progress.
* Inspect every generated result.

The workflow should remain clean regardless of whether the user generates:

* 5 videos
* 30 videos
* 100 videos

⸻

New Data Type

Introduce a new workflow data type.

Collection<T>

Examples:

Collection<Video>
Collection<Image>
Collection<Text>
Collection<Audio>

Nodes must be capable of accepting either:

* Single Item
* Collection

Style Blueprint

Before generating variations, analyze the original video and build a reusable blueprint.

The blueprint should capture:

* Editing rhythm
* Speaker identity
* Color grading
* Caption style
* Font usage
* Transition style
* Camera movement
* Visual pacing
* Hook style
* Tone
* Brand identity

Every generated variation should reference this blueprint.

Do not generate videos from scratch.

Generate variations from the blueprint.

⸻

Execution Model

When the user selects:

Generate 30

Create:

30 execution jobs

Example:

Job 1
Job 2
Job 3
...
Job 30

These jobs execute in parallel when resources allow.

The canvas should still display only one node.

⸻

Collection-Aware Nodes

Every downstream node should automatically iterate through collections.

Example:

Collection<Video>
↓
Caption Generator
↓
Collection<Caption>

Then:

Collection<Caption>
↓
Thumbnail Generator
↓
Collection<Thumbnail>

No manual loops should be required.

⸻

Automatic Iteration

If a node receives:

Collection<T>

The engine should automatically:

For each item
Run node
Collect result
Return Collection

The user should never have to configure iteration manually.

Future Collection Types

The architecture should support:

Collection<Image>
Collection<Podcast>

Collection<Email>
Collection<Post>

This allows the same workflow engine to power all AI content generation features.

⸻

Scalability

The execution engine should support:

* Parallel execution
* Queued execution
* Retry failed jobs
* Pause
* Resume
* Cancel
* Progress tracking

⸻

Performance Goals

The workflow canvas should remain responsive even when generating:

* 30 outputs
* 100 outputs
* 500 outputs

Execution complexity must never affect canvas performance.

⸻

Success Criteria

The implementation is complete when:

* One source video can generate multiple variations.
* The canvas displays only a single Batch Generator node.
* Variations preserve the original style using the Style Blueprint.
* Downstream nodes automatically process collections.
* Users can monitor progress.
* Users can inspect individual outputs.
* The system scales cleanly without adding duplicate nodes to the workflow.
