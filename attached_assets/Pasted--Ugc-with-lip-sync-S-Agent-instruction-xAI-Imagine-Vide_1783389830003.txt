## 1. Auth

API key starts with `xai-`. Pass it as a Bearer token:

```bash
export XAI_API_KEY="xai-..."
```

**Browser / client-side**: never expose the API key. Proxy through your backend.

**SDKs:** Prefer an official SDK over raw HTTP when it fits the stack — Python: `xai-sdk` (`pip install xai-sdk`), JavaScript: Vercel AI SDK (`npm install ai @ai-sdk/xai`). Both handle video result polling automatically.

## 2. API Endpoint

```
POST https://api.x.ai/v1/videos/generations
```

**Headers:**
- `Authorization: Bearer <API_KEY>`
- `Content-Type: application/json`

## 4. Input media

This request includes an input image. The `url` field accepts either:
- A **public URL** pointing to the file, or
- A **base64-encoded data URI** (e.g. `data:image/png;base64,...`).

To send a local file, read it and encode it as a data URI before building the request body. Never paste an in-memory/blob URL — it is not reachable by the API.

## 6. Polling for the result (video only)

Video generation is asynchronous. The generation request returns a `request_id`. Poll the result endpoint until `video.url` is present:

```
GET https://api.x.ai/v1/videos/<REQUEST_ID>
```

The poll response looks like:

```json
{ "model": "...", "progress": 100, "video": { "url": "https://...", "duration": 6 } }
```

While generating, `video` is absent and `progress` counts up to 100. On failure the response contains an `error` object with `code` and `message`. Poll every ~5 seconds.

## 7. Error Handling

| Status | Meaning | Action |
|---|---|---|
| 200 | Success | Poll the result endpoint |
| 400 | Bad request | Check the prompt, model, and parameters |
| 401 | Unauthorized | Invalid or missing API key |
| 402 | Payment required | Add credits to the team at [console.x.ai](https://console.x.ai) → Billing |
| 429 | Rate limited | Exponential backoff: e.g. 5 retries, 1s base delay, doubling with jitter |
| 500+ | Server error | Same backoff strategy as 429 |
