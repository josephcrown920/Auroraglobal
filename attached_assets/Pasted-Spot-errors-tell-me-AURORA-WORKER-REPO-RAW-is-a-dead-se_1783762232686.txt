Also do I have to always manually open o kaggle and collab before for the GPU works?
Yes — that's the trade-off with free GPUs. Kaggle and Colab workers only exist while the notebook session is running:

The tab has to stay open (Kaggle kills the session shortly after you close it; Colab even faster on the free tier)
Sessions have hard time limits — roughly 9–12 hours max per session
Kaggle gives you ~30 GPU hours per week total; when the quota runs out, no worker until it resets
When the session dies, the health checker notices within ~5 minutes and pauses the worker — that's exactly why yours was paused when we started
So the realistic patterns are:

On-demand (free): open Kaggle when you plan to use lip-sync, run the cell, use the app, close it when done. With your static ngrok domain, re-running reuses the same worker row — but note that today you also need to manually unpause it in Admin each time, since the system deliberately doesn't let a re-registration override a paused status.
Always-on (paid): a rented GPU like the Vast instance we just discussed runs 24/7 for as long as you keep paying — no tabs, no quotas. That's the only way to have workers permanently online.
Hybrid: most apps do paid API fallback for image/video (which Aurora already does), and self-hosted only for lip-sync/motion, spun up when needed.
