Master Prompt

You are performing a full application UI migration, not a landing page redesign.

The new UI is the single source of truth. Replace the old design everywhere in the application.

Objective

Migrate every page, route, layout, component, modal, dialog, dashboard, settings page, authentication page, profile page, tables, forms, navigation element, and reusable component to match the new design system.

Do NOT stop after updating the first visible page.

Required Workflow

Phase 1 — Audit

Before writing code:

* Discover the entire route tree.
* Discover every page.
* Discover every shared component.
* Discover every layout.
* Discover every modal.
* Discover every dialog.
* Discover every sidebar.
* Discover every navigation component.
* Discover every dashboard view.
* Discover all feature modules.

Produce a checklist of everything that must be migrated.

Do not begin implementation until the audit is complete.

⸻

Phase 2 — Migration

Systematically migrate every discovered item.

For every page:

* Replace old styling.
* Replace old spacing.
* Replace typography.
* Replace colors.
* Replace icons.
* Replace cards.
* Replace buttons.
* Replace inputs.
* Replace tables.
* Replace navigation.
* Replace responsive layouts.
* Replace loading states.
* Replace empty states.
* Replace error states.

Maintain functionality.

Do not leave mixed old/new UI.

⸻

Phase 3 — Component Refactor

Find duplicate UI.

Extract reusable components.

Ensure every page uses the same design system.

No copied styling.

No inline duplicated components.

⸻

Phase 4 — Verification

When coding is complete:

Check every route.

Check every page.

Check every modal.

Check every dashboard.

Check every feature.

Check mobile.

Check tablet.

Check desktop.

Check dark/light mode if applicable.

Verify there is zero remaining legacy UI.

⸻

Completion Rules

You are NOT finished because the homepage looks correct.

You are finished only when:

* every route uses the new UI
* every shared component has been migrated
* every page matches the design system
* no legacy styling remains
* no placeholder components remain
* no page is skipped

⸻

Iteration Rules

After implementation:

Run another audit.

Compare the entire application against the design system.

If even one page or component still uses the previous design, continue migrating automatically.

Repeat until no legacy UI exists.

Never stop after one iteration.

⸻

Important

Do NOT assume the first page represents the whole application.

Treat this as a repository-wide migration.

Think globally before coding locally.

Always search the entire codebase before making changes.

Never stop after modifying a single route.

⸻

If you’re using agents like Claude Code, Cursor, Windsurf, or OpenAI Codex, an additional instruction often helps:

Do not optimize for speed. Optimize for completeness. Spend as much time as needed auditing the repository before making changes. Your success criterion is 100% UI migration coverage, not passing the first visual inspection. If necessary, make multiple implementation passes automatically until no legacy UI remains.

This changes the agent’s goal from “make something look right” to “finish a complete migration,” which greatly reduces the need for repeated back-and-forth fixes.
