## 🚨 CRITICAL FIX #1: Credit Ledger Unbounded Read (§8.2)

### Problem
`src/lib/cost-guardrails.server.ts` → `assertDailyBudget()` reads **ALL** credit_ledger rows for today, sums them in JavaScript. On high-volume users, this becomes slow and is a financial correctness risk (naive "fix" with `.limit()` silently undercounts spend).

### Root Cause
```typescript
// CURRENT (BROKEN): unbounded read for every spend check
const { data } = await supabaseAdmin
  .from("credit_ledger")
  .select("delta, reason")
  .eq("user_id", userId)
  .gte("created_at", dayStart);
// If user has 500+ ledger entries today, this reads all 500 rows.
```

### Solution
Use Supabase RPC to compute the sum **server-side**, not client-side:

**Step 1: Run this SQL migration (or add to your migrations):**
```sql
-- Track daily spend incrementally without full table scan
create table if not exists daily_spend_summary (
  user_id uuid not null,
  day_date date not null,
  total_spent numeric not null default 0,
  updated_at timestamp not null default now(),
  primary key (user_id, day_date)
);

-- RPC to atomically fetch or compute today's spend (race-free)
create or replace function get_daily_spend(
  _user uuid,
  _day_start timestamp
)
returns numeric as $$
  select coalesce(sum(-(delta)), 0)
  from credit_ledger
  where user_id = _user
    and created_at >= _day_start
    and (reason like 'reserve:%' or reason like 'release:%');
$$ language sql stable;
```

**Step 2: Update `src/lib/cost-guardrails.server.ts`:**

Replace the `getLedgerRows` function:

```typescript
// OLD (inefficient):
getLedgerRows: async (userId, dayStart) => {
  const { data } = await supabaseAdmin
    .from("credit_ledger")
    .select("delta, reason")
    .eq("user_id", userId)
    .gte("created_at", dayStart);
  return (data as { delta: number; reason: string }[] | null) ?? [];
},

// NEW (efficient, server-side):
getLedgerRows: async (userId, dayStart) => {
  const client = supabaseAdmin as unknown as { rpc: (name: string, args: Record<string, unknown>) => Promise<{ data: number; error: { message: string } | null }> };
  const { data: totalSpent, error } = await client.rpc("get_daily_spend", {
    _user: userId,
    _day_start: dayStart,
  });
  if (error) throw new Error(`Failed to fetch daily spend: ${error.message}`);
  return [{ delta: -(totalSpent as number), reason: "reserve:aggregated" }];
},
```

Then simplify `assertDailyBudget`:

```typescript
export async function assertDailyBudget(
  userId: string,
  estimatedCost: number,
  deps: DailyBudgetDeps = defaultDailyBudgetDeps,
): Promise<void> {
  const profile = await deps.getProfile(userId);
  const limit = profile?.daily_spend_limit ?? null;
  if (!limit) return;

  const dayStartUtc = new Date();
  dayStartUtc.setUTCHours(0, 0, 0, 0);
  const rows = await deps.getLedgerRows(userId, dayStartUtc.toISOString());
  
  // Single row now (aggregated), same math:
  const spentToday = rows.reduce((sum, r) => sum - r.delta, 0);

  if (spentToday + estimatedCost > limit) {
    throw new Error(
      `Unsupported: daily_limit_reached — you've used ${spentToday} of your ${limit} Aura daily limit. Raise or clear your limit in Billing, or try again tomorrow.`,
    );
  }
}
```

### Test Coverage
Add to `src/lib/cost-guardrails.test.ts`:
```typescript
describe("assertDailyBudget", () => {
  it("computes daily spend correctly with high-volume ledger", async () => {
    // Mock 500 ledger entries

        { delta: -50, reason: "reserve:aggregated" },

      ],
    };

```

## 🎬 CRITICAL FIX #2: Aurora Soul Video Generation Secrets (§16)

### Problem
`generateSoulVideo()` in `src/lib/soul.server.ts` calls Seedance API for character video generation, but `SEEDANCE_API_URL` and `SEEDANCE_API_KEY` are not configured. Video generation returns 500 errors.

### Solution

**Step 1: Get your Seedance credentials:**
- Contact fal.ai or your Seedance partner
- You'll receive `SEEDANCE_API_URL` (usually `https://api.seedance.ai` or similar) and `SEEDANCE_API_KEY`

**Step 2: Add to your `.env` (or Replit Secrets):**
```env
SEEDANCE_API_URL=https://api.seedance.ai
SEEDANCE_API_KEY=your_seedance_api_key_here
SOUL_FAL_WEBHOOK_SECRET=your_random_webhook_secret_here
```

**Step 3: Update `src/lib/orchestrator.server.ts`** to use these vars:

Find this section and add Seedance:

```typescript
// In the orchestration adapter list, add:
export const seedanceAdapter = async (params: OrchestrateParams) => {
  const apiUrl = process.env.SEEDANCE_API_URL;
  const apiKey = process.env.SEEDANCE_API_KEY;
  
  if (!apiUrl || !apiKey) {
    throw new Error("Seedance not configured (SEEDANCE_API_URL or SEEDANCE_API_KEY missing)");
  }
  
  if (params.kind !== "video" || params.model !== SOUL_VIDEO_MODEL) {
    return null; // not for this request
  }
  
  const res = await fetch(`${apiUrl}/generate`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${apiKey}`,
    },
    body: JSON.stringify({
      prompt: params.prompt,
      duration: params.duration || 10,
      aspect_ratio: params.aspectRatio || "16:9",
      reference_images: params.imageUrls || [],
    }),
  });
  
  if (!res.ok) {
    const body = await res.text();
    throw new Error(`Seedance request failed [${res.status}]: ${body.slice(0, 200)}`);
  }
  
  const json = (await res.json()) as { video_url?: string; job_id?: string };
  return {
    url: json.video_url || "",
    jobId: json.job_id,
  };
};
```

**Step 4: Add Seedance to the orchestration priority chain** (in `orchestrator.server.ts`):

```typescript
// For Soul video (SOUL_VIDEO_MODEL):
const videoChain = [
  seedanceAdapter,        // ← Add this (highest priority for Soul videos)
  klingDirectAdapter,     // fallback to Kling
  replicateAdapter,       // fallback to Replicate
  falFallbackAdapter,     // final fallback
];
```

**Step 5: Validate in Replit** by testing the `/api/soul/generate-video` endpoint:
```bash
curl -X POST http://localhost:5173/api/soul/generate-video \
  -H "Content-Type: application/json" \
  -d '{"soulId":"test-soul","prompt":"character video","duration":10}'
```

## 🔐 MEDIUM FIX #1: OAuth Providers Setup (§11)

### Problem
Google and Apple OAuth are disabled. Users trying to sign in via those providers get "provider is not enabled" error.

### Solution

#### **Google OAuth:**

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Select your project (or create one)
3. APIs & Services → Credentials
4. Create OAuth 2.0 Client ID (Web application)
5. Authorized redirect URIs:
   ```
   https://your-aurora-deployment.replit.dev/auth/callback/google
   https://localhost:3000/auth/callback/google
   ```
6. Copy Client ID and Client Secret

7. In your Supabase dashboard:
   - Auth → Providers → Google
   - Paste Client ID and Client Secret
   - Click "Save"

#### **Apple OAuth:**

⚠️ **Requires paid Apple Developer Account ($99/year)**

1. Get an Apple Developer account if you don't have one
2. Create a new "Service ID" for your app
3. Register the "Sign in with Apple" capability
4. Generate a key (save the `.p8` file and note the Key ID)
5. Get your Team ID from Apple Developer settings

6. In your Supabase dashboard:
   - Auth → Providers → Apple
   - Paste Team ID, Key ID, and `.p8` contents
   - Click "Save"

**After setup, test:**
```bash
# Visit your app and check OAuth buttons are active
https://your-aurora-deployment.replit.dev/auth/signin
```
