Aurora Global — Production Readiness Checklist

🔴 Phase 1 — Critical Production Blockers

CI / Automated Quality Gates

* Create GitHub Actions CI workflow.
* Run TypeScript typecheck on every PR.
* Run lint on every PR.
* Run unit/integration tests on every PR.
* Run Playwright E2E tests on every PR.
* Run production build in CI.
* Fail PRs automatically when checks fail.
* Add dependency/security scanning.
* Add a protected main branch requiring CI to pass.

Supabase Database

* Audit the current Supabase database against the application code.
* Identify every required table, function, trigger, index, RLS policy, and enum.
* Generate/populate supabase/migrations/.
* Ensure migrations create gpu_workers.
* Ensure migrations create worker_jobs.
* Ensure migrations create all media/job/payment-related tables.
* Verify all RLS policies.
* Test migrations against a clean staging Supabase project.
* Document migration deployment procedure.
* Document rollback/recovery procedure.
* Verify pg_cron is configured.
* Verify /api/public/jobs/tick cron execution.
* Verify /api/public/workers/health cron execution.
* Confirm cron failures are observable.

🔐 Secrets / Environment

* Inventory every production environment variable.
* Compare .env.example against actual application usage.
* Verify Lovable Cloud secret injection.
* Verify Supabase URL/key configuration.
* Verify FAL credentials.
* Verify Kling credentials.
* Verify Paystack credentials.
* Verify provider-specific secrets are never exposed to the browser.
* Search repository/history for accidentally committed secrets.
* Establish a documented secret rotation procedure.
* Test production startup with missing/invalid secrets.
* Ensure failures produce useful diagnostics without exposing secret values.

⸻

🟠 Phase 2 — Runtime & Infrastructure Hardening

Cloudflare Workers Compatibility

* Audit every Node-specific dependency.
* Audit all imports of sharp.
* Audit child_process, filesystem, process, Buffer, and other Node APIs.
* Confirm server-only modules cannot enter the Cloudflare client bundle.
* Confirm sharp is never required by Cloudflare Worker runtime code.
* Run a clean production Cloudflare build.
* Test the actual deployed Worker rather than relying only on local development.
* Separate Node/GPU/server workloads from Cloudflare Worker workloads where necessary.
* Add build-time checks for unsupported Worker dependencies.

Deployment

* Document the complete production deployment flow.
* Create automated Cloudflare Worker deployment.
* Define staging vs production environments.
* Add deployment verification/smoke tests.
* Add production rollback procedure.
* Verify Supabase deployment occurs safely alongside application deployment.
* Ensure GPU workers can be deployed independently of the web application.

⸻

🟢 Phase 4 — Observability

Error Monitoring

* Add Sentry or equivalent runtime error monitoring.
* Capture frontend exceptions.
* Capture server exceptions.
* Capture Worker failures.
* Capture provider failures.
* Capture queue failures.
* Add deployment/environment information to errors.

Metrics

* Track generation requests.
* Track successful generations.
* Track failed generations.
* Track provider latency.
* Track provider failure rate.
* Track fallback frequency.
* Track queue depth.
* Track job processing time.
* Track GPU worker availability.
* Track payment failures.

Alerts

* Alert on elevated generation failures.
* Alert when provider failure rate spikes.
* Alert when queue backlog grows.
* Alert when GPU workers disappear.
* Alert when cron stops running.
* Alert on repeated deployment failures.

🔵 Phase 5 — Security

* Audit Supabase RLS policies.
* Verify users cannot access another user’s jobs.
* Verify users cannot access another user’s generated media.
* Verify worker authentication.
* Verify public API rate limiting.
* Add generation abuse protection.
* Validate uploaded files.
* Validate provider callback/webhook signatures.
* Prevent duplicate payment processing.
* Review CORS configuration.
* Review CSP/security headers.
* Audit dependency vulnerabilities.
* Remove unused dependencies.
* Review exposed API routes.
* Verify admin/operator endpoints are protected.

⸻

🟣 Phase 6 — Architecture Cleanup

Licensing

* Resolve the mismatch between proprietary Aurora Studio licensing and the CLI’s MIT license.
* Decide exactly which components are proprietary.
* Document third-party licenses.
* Document provider/model licensing requirements.
* Confirm redistribution restrictions for integrated AI models/services.

Repository

* Review generated routeTree.gen.ts.
* Confirm generated artifacts are intentionally committed.
* Document generation process.
* Remove unnecessary files/dependencies.
* Review package versions.
* Lock dependency versions appropriately.
* Verify Bun/Node compatibility.
* Document supported Node/Bun versions.

⸻

🧪 Phase 7 — Production Smoke Test

Before declaring production-ready:

* Fresh install succeeds.
* Development server starts.
* Production build succeeds.
* Production deployment succeeds.
* User can sign up.
* User can sign in.
* User can create a generation job.
* Job enters queue.
* Worker receives job.
* Provider generates media.
* Media is stored correctly.
* Job reaches completed state.
* Failed provider triggers fallback.
* Failed worker triggers recovery/fallback.
* User receives correct job status.
* Payment succeeds.
* Credits/balance update correctly.
* Cron executes.
* Worker health monitoring executes.
* Errors appear in monitoring.
* Alerts trigger correctly.
* No secrets appear in client/network responses.
* No cross-user data access is possible.
* Rollback procedure has been tested.

⸻

🎯 Definition of Production Ready

Minimum target: 8/10

* CI is green.
* Database migrations are complete.
* Production deployment is reproducible.
* Cloudflare runtime compatibility is verified.
* Secrets are verified.
* Critical E2E tests pass.
* Provider fallback is tested.
* GPU worker lifecycle is tested.
* Monitoring is active.
* Security/RLS audit passes.

Target: 9/10

* Automated deployment.
* Staging environment.
* Automated smoke tests after deployment.
* Full provider failure testing.
* Queue observability.
* Automated rollback capability.
* Security scanning.
* Load/performance testing.
* Disaster recovery procedure.
* Documented operational runbook.
