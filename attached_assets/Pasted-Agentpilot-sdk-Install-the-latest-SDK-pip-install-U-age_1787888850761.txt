# Overview

AgentPilot SDK provides tools, APIs, and resources to streamline application development and help developers build agents. It integrates PromptPilot's core capabilities in a non\-intrusive and flexible way.

<span id="04985e67"></span>
## Features

**The core value of the SDK** : through automated probing, **obtain high\-quality feedback data at low cost** , thereby building an efficient, sustainable model optimization loop. This closed loop helps the agent better adapt to the scaling law.


* Reduce data collection costs

* Help the Agent adapt to the Scaling Law


Specifically, users can freely compose PromptPilot's internal atomic capabilities in a low\-intrusion and flexible way. The tools, APIs, and resources provided by the SDK simplify application development and help developers quickly integrate PromptPilot's core features, including but not limited to:


|**Features** |**Brief description** |
|---|---|
|Task and prompt management |Manage tasks and prompts directly via the SDK, and read and list version information, model configuration, and scoring criteria. |
|Closed\-loop data and feedback |Support a completion API compatible with the Ark client, enabling users to send data and feedback back to the PromptPilot page during inference. |
|Prompt optimization and report retrieval |Submit prompt optimization tasks via the SDK and retrieve evaluation reports. |
|Online evaluation |Submit custom evaluation requests and obtain results. Sending the results back is optional. |
|Bad case detection |Determine which samples are bad cases based on the evaluation score and confidence, and label them on the console page. |
|Prompt generation |Generate a prompt based on `task_description`. |


<span id="f8b1b65d"></span>
## Advantages

Guided by design principles of ease of use, modularity, extensibility, and openness, we strive to ensure:


* Low intrusion (ease of use): Modify only a few lines in existing agent or workflow code to implement the features listed in this document. Integration is simple.

* Modularity: Use modules individually or in any combination, such as evaluation, backflow, feedback, and prompt optimization.

* Extensibility and openness: Support multiple AI models, APIs, and multimodal data; seamlessly support open\-source frameworks such as LiteLLM, LangChain, and LlamaIndex for LLM or agent application development; and make it easy to extend use cases using existing capabilities.


<span id="00693238"></span>
## Core concepts

**Tasks and versions (task and version)**  :

The diagram below shows the mapping between the PromptPilot Console and the SDK. A task is typically created under a personal or team workspace, and it usually contains multiple prompt versions. Each version centers on a prompt and includes related version information, such as `task_id`, `version`, `prompt`, a variable list, evaluation criteria (`criteria`), the model name, and configurations such as `temperature` and `top_p`.

To stream data back via the SDK, users typically include `workspace_id` (to specify a workspace), `task_id`, `version`, `AGENTPILOT_API_KEY` (authentication for the ingestion service), and `ARK_API_KEY` (model inference on ModelArk) in the request. This covers most operations.

**Ingestion event (run)**  :

If a model call is sampled, it produces one ingestion event. Each ingestion event corresponds to one row on the platform's Batch page.

<span id="cb6ec355"></span>
# Precautions


* **Ingestion sampling rate** : The default sampling rate is 0.1, meaning each record has a 0.1 probability of being ingested. You can adjust it as needed.

* **Ingestion data cap** : The default is 2,000 records. If the number of records under a given `task_id` and `version` exceeds 2,000, ingestion fails and the SDK call returns a log message. This limit aligns with the console page. To increase the limit, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

* **Only the scoring mode for text understanding and visual understanding tasks is currently supported.**  If you need support for more task types, such as multi\-turn conversations and Tools, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

* **`model_name`** ** is the model name plus version and must be a model supported in the model dropdown on the Prompt Generation page.**  If you need support for custom or third\-party endpoints, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

## 2. Data reporting and feedback

<span id="cef986a1"></span>
### How do I create an Ark client that can report data back?

Call the `ap.probing()` API to apply a patch to an Ark client. After that, the client can be used for model inference calls and can also send data back to a specific task in the console.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os

# Create client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client)
```


<span id="b1e75ce6"></span>
### How do I automatically report data?

Call `ap.render()` to render `task_id`, `version`, and variables, obtain the rendered `input_dict`, and pass it to the Ark client when calling the completion API. The system automatically retrieves the corresponding prompt version, assembles it into the input of the LLM inference request, and obtains the model answer. The completion API for LLM requests is compatible with the Ark client.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os

# Create client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render input for the inference request
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    api_key=None,
    api_url=None,
)

# Call Model inference, as with the ModelArk SDK
completion = client.chat.completions.create(model='seed-1.6-250615', **input_dict)

# Optional step: flush pending event messages in the queue and send them immediately. If you don't flush, the system automatically backfills in small scheduled batches to improve performance
ap.flush()

# Print the completion result
print(completion.choices[0].message)

# Print the event run_id, which corresponds to a row on the Batch page and is used for subsequent tracking, editing, and overwriting data
print(completion.run.id)
```


If successful, you will see the model completion and the `run_id` of this data record. At this point, log in to the console page to view a newly added data record, including variables and the model answer.

Then the prompt could be: "Please answer the question based on the following context text. ```

### How do I manually write back data?

In addition to automatically writing back data via the completion API, the SDK also lets you write back data manually. You can also override data after the automatic write\-back, such as adding an ideal answer (reference) or updating variables.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os
import time
import uuid

# Create a run_id or obtain the run_id of a backfill event from the above completion API response
run_id = str(uuid.uuid4())
task_id = "ta-20250101000000-aaaaa"
version = "v1"

# Backfill or overwrite the row of data corresponding to a run_id
ap.track_event(
    run_type="llm",
    event_name="reference",  # Backfill event name; any name is acceptable
    run_id=run_id,
    task_id=task_id,
    version=version,
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    input_messages=[{"role": "user", "content": "This is a model input"}],
    output_message={"role": "user", "content": "This is a model output"},
    reference="This is a reference answer",
    api_key=None,
    api_url=None,
)
ap.flush()
```

### How do I provide human feedback scores?

After applying the patch, the Ark client is almost identical to the standard Ark completion API, except that the inference return value `completion` carries a write\-back event (`run`) as the unique identifier (`run.id`) for subsequent tracking (`track`) of a data record. As long as you have this identifier, you can append follow\-up actions, such as adding human scores and AI scores.

Continue from the code above: call the `ap.track_feedback()` API and pass a feedback dict. Provide human scoring data through the `human_score`, `human_analysis`, and `human_confidence` fields. After ingestion, log in to the console to view the record mentioned above; it now includes the score and scoring reason. This feature aligns with the console's manual scoring feature.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os

# Create the client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render the inference request input
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    api_key=None,
    api_url=None,
)

# Call Model inference, same as the ModelArk SDK
completion = client.chat.completions.create(model='seed-1.6-250615', **input_dict)

# Optional step: flush pending event messages in the queue and send them immediately. If you don't flush, the system automatically flushes small batches on a schedule to improve performance
ap.flush()

# Print completion results
print(completion.choices[0].message)

# Print the event run_id, which corresponds to a row on the Batch page and can be used for subsequent tracking, editing, or overwriting data
print(completion.run.id)

# Get the unique identifier run.id of the above event run
run = completion.run
if run is not None:
    print(run.task_id)
    print(run.version)
    print(run.id)

# Track and add human feedback scores
ap.track_feedback(
    task_id=run.task_id,
    version=run.version,
    run_id=run.id,
    feedback={
        "human_score": 5,
        "human_analysis": "The reason for manual scoring of this data",
        "human_confidence": 1.0,
    },
)

ap.flush()
```


If it runs successfully, log in to the Batch page under this task in PromptPilot; you will see that the ingested data now includes the score and scoring reason.

<span id="03d5573c"></span>
### How do I submit an online evaluation request?

Call the `ap.eval.evaluate()` API. Enter an example and a metric, both dicts, and provide the relevant fields.

```Python
import agent_pilot as ap

# Samples to evaluate
example = {
    "prompt": "This is a prompt template, it contains {{variable_1}} and {{variable_2}}",
    "variables": {
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    "response": "Content of model response",
}

# Scoring criteria
metric = {
    "criteria": "The text is fluent and logically clear. Obtaining 5 points if the response content is sufficient and there are no obvious omissions; otherwise, output the number 1."
}

# Run evaluation
result = ap.eval.evaluate(
    example=example,
    metric=metric,
    api_key=None,
    api_url=None,
)
print(result)
```


If successful, you will see the following output.

```Bash
example_id=None
reference=None
score=1
analysis="The task question did not clearly specify the requirements. The model's response did not reflect the processing of the content of variable 1 and variable 2. The response content was insufficient and there were obvious omissions, failing to meet the requirement in the evaluation criteria that the response content should be sufficient and have no obvious omissions. Therefore, the score is 1."
confidence=0.9
```


Specifically, we provide the following optional parameters:


* `example_id`: Users can specify this ID to map each sample to its evaluation result one\-to\-one, making lookup easier.

* `reference`: If the scoring criteria (`criteria`) requires comparing the model answer with a reference answer, use this field to pass the sample's reference answer. For example, `criteria`: "The model answer matches the reference answer."

### How do I feed back the AI score?

The process is the same as feeding back human scores: track the event using the unique identifier (`run.id`) of the feedback event (`run`), then call the `ap.track_feedback()` API and pass feedback to add the AI score.

Unlike human scores, the AI score requires passing the `human_score`, `human_analysis`, and `human_confidence` fields as feedback. After feedback is sent, log in to the console page to see that the sample corresponding to `run.id` has updated its score and scoring reason, and the label "AI Score" is displayed next to it. This feature aligns with the intelligent scoring feature on the console page.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os
import time

# Create client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render the inference request input
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
)

# Invoke Model inference, same as with the ModelArk SDK
completion = client.chat.completions.create(model='1.5-pro-32k-250115', **input_dict)
print(completion.choices[0].message)

run = completion.run

if run is not None:
    result = ap.eval.evaluate(
        example={
            "example_id": "example_id_1",
            "input": input_dict["messages"][0]["content"][0]["text"],
            "response": completion.choices[0].message.content,
        },
        metric={
            "criteria": "The text is fluent and logically clear. If the response content is sufficient and there are no obvious omissions, score 5 and output the number 5. Otherwise, output the number 1."
        },
        api_key=None,
        api_url=None,
    )
    print(result)

    ap.track_feedback(
        task_id=run.task_id,
        version=run.version,
        run_id=run.id,
        feedback={
            "metric_score": result.score,
            "metric_analysis": result.analysis,
            "metric_confidence": result.confidence,
        },
    )

    ap.flush()
```


If the run succeeds, log in to PromptPilot and go to the Batch page for this task. You will see that the returned data includes the score and scoring reason, and the score is labeled "AI Score".

### How do I view optimization status and progress?

Using the `opt_job` object, call `opt_job.get_job_info()` to view the current optimization job information, including state and progress.


* When optimization finishes, `state` is one of `{ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED}`. If it is neither, wait briefly and query again.

* While optimization is running, `state` is one of `{ap.OptimizeState.CREATED, ap.OptimizeState.RUNNING}`.


Continuing from the code above, query the optimization job information every 5 seconds:

```Python
import agent_pilot as ap
import time

# Call ap.optimize.create() to create an optimization job
opt_job = ap.optimize.create(task_id="ta-20250101000000-aaaaa", base_version="v1", api_key=None, api_url=None)
print(opt_job)

# Query JobInfo via the opt_job object
job_info = opt_job.get_job_info()
while job_info.state not in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED}:
    # View the current state
    print(job_info.state)
    # View the current progress
    if job_info.progress is not None:
        print(job_info.progress.percent)         # Current optimization job completion percentage
        print(job_info.progress.optimal_prompt)  # Current optimal prompt
        print(job_info.optimized_version)

    # Re-fetch JobInfo after 5 seconds
    time.sleep(5)
    job_info = opt_job.get_job_info()

# After the optimization job completes, the status is SUCCESS or FAILED
print(job_info.state in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED})
```

### How do I obtain the optimization report?

If optimization succeeds, call the `opt_job.get_report()` API to obtain the optimization report.

```Python

import time

# Call the API ap.optimize.create() to create an optimization job
opt_job = ap.optimize.create(task_id="ta-20250912125011-WDAtF", base_version="v1", api_key=None, api_url=None)

job_info = opt_job.get_job_info()

    # View the current state
    print(job_info.state)
    # View current progress
    if job_info.progress is not None:
        print(job_info.progress.percent)         # Completion percentage of the current optimization job
        print(job_info.progress.optimal_prompt)  # Current best prompt
        print(job_info.optimized_version)

    # Retrieve JobInfo again after 5 seconds
    time.sleep(5)
    job_info = opt_job.get_job_info()

# After the optimization job ends, the status is SUCCESS or FAILED
print(job_info.state in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED})

if job_info.state == ap.OptimizeState.SUCCESS:
    report = opt_job.get_report()
    opt, base = report.opt, report.base

    # Compare prompts before and after optimization
    print(opt.prompt, base.prompt)

    # Compare metrics before and after optimization
    print(opt.metric, base.metric)

    # Compare average scores before and after optimization
    print(opt.avg_score, base.avg_score)

    # List data records before and after optimization
    print(opt.records, base.records)

## 5. Prompt generation

Call the `ap.generate_prompt_stream()` API, pass `task_description` and the model configuration, and generate the prompt as a stream. This capability aligns with the Prompt Generation page in the console.

The following example generates a prompt for a multi\-turn conversation task. To generate prompts for text understanding or visual understanding, set `task_type` to `"DEFAULT"` or `"MULTIMODAL"`, respectively.

```Python
import agent_pilot as ap

generated_prompt = ""
usage = None
print("Streaming response:")
for chunk in ap.generate_prompt_stream(
    task_description="I need a top-tier live streaming sales assistant; input is user's question, output is product introduction",
    task_type="DIALOG",
    model_name="seed-1-6-250615",
    temperature=1.0,
    top_p=0.7,
    api_key=None,
    api_url=None,
):
    # Handle streaming output
    generated_prompt += chunk.data.content
    print(chunk.data.content, end="", flush=True)
    if chunk.event == "usage":
        usage = chunk.data.usage

print(f"Generated prompt: {str(generated_prompt)}")
print(f"Usage: {usage}")
```

# Role Positioning: Top Live Streaming Sales Expert
You are a highly engaging and persuasive live streaming sales expert, skilled at accurately understanding user needs and using vivid, alluring language to stimulate purchasing desire, making users develop an intense desire to own after listening to your introduction. Your core task is: no matter what product-related questions users ask (such as functions, prices, advantages, applicable scenarios, etc.), you can quickly transform them into targeted product introductions to achieve "question = planting the seed of purchase".


# Core Live Streaming Sales Strategies
## 1. Demand Anchoring Method
- First, quickly capture the potential needs in the user's question (e.g., if a user asks "What skincare product is not greasy in summer?", the need is "refreshing and oil-controlling"), and directly state it at the beginning of the answer: "Are you looking for a product that feels like water when applied, can keep your skin matte even with more oil in summer?"
- Use phrases like "Are you", "I understand you", "Many people have encountered this" to build empathy, making users feel "You completely understand me".


## 2. Product Highlight Blasting
- Targeting the user's needs, extract 3 core highlights of the product, and use exaggerated but true effect descriptions like "3-second results", "amazing after use", "can't live without it" to strengthen memory points.
- Pair each highlight with a specific scenario: "For example, in the morning when you're in a hurry, applying it takes 2 minutes and you can go out; your face won't be oily all day, and colleagues will think you secretly touched up your makeup!"


## 3. Creating Urgency and Scarcity
- Actively reveal hidden benefits': 'Now placing an order not only gets a 50-yuan discount, but the first 100 orders also include a free sample of the same product; only 3 sets of inventory left!'
- Use phrases like "Miss today and wait another year", "This color has long been out of stock in offline counters, only 50 pieces left online" to stimulate decision-making.


## 4. Comparison and Crushing Strategy
- If the user mentions competitors or hesitates, directly use "crushing comparison" to highlight advantages: "I know the one you're talking about; its XX function requires separate payment to activate, while ours is directly free, and the effect is 3 times stronger than it!"
- Emphasize "king of cost-effectiveness": "At the same price, others can only buy the basic version; our product gives one for free and three as gifts, which is equivalent to earning two products for free!"


# Dialogue Process and Taboos
## Must-Do Process
1. **Catch the question → Anchor the need → Blast highlights → Create scarcity → Urge to place an order**, all within 3 sentences, with a tight rhythm, leaving no room for user hesitation.
2. Each answer must end with a clear call to action: "Click the link below to grab directly", "Placing an order now can be delivered by SF Express tomorrow", "Hurry to check, no stock left for slow hands!"


## Absolute Taboos
- Prohibit using vague words like "maybe", "perhaps", etc.; must use affirmative tones like "100% effective", "absolutely good", "who uses knows".
- Prohibit long introductions. If a user asks "How much?", directly reply: "Original price 299, today's promotional price 199, plus a free 99-yuan gift, which is equivalent to buying 3 items for only 100 yuan. Will you place an order now?"

Remember: Every word you say should be like a hook, hooking users' ears and even more hooking their wallets!

# Overview

AgentPilot SDK provides tools, APIs, and resources to streamline application development and help developers build agents. It integrates PromptPilot's core capabilities in a non\-intrusive and flexible way.

<span id="04985e67"></span>
## Features

**The core value of the SDK** : through automated probing, **obtain high\-quality feedback data at low cost** , thereby building an efficient, sustainable model optimization loop. This closed loop helps the agent better adapt to the scaling law.


* Reduce data collection costs

* Help the Agent adapt to the Scaling Law


Specifically, users can freely compose PromptPilot's internal atomic capabilities in a low\-intrusion and flexible way. The tools, APIs, and resources provided by the SDK simplify application development and help developers quickly integrate PromptPilot's core features, including but not limited to:


|**Features** |**Brief description** |
|---|---|
|Task and prompt management |Manage tasks and prompts directly via the SDK, and read and list version information, model configuration, and scoring criteria. |
|Closed\-loop data and feedback |Support a completion API compatible with the Ark client, enabling users to send data and feedback back to the PromptPilot page during inference. |
|Prompt optimization and report retrieval |Submit prompt optimization tasks via the SDK and retrieve evaluation reports. |
|Online evaluation |Submit custom evaluation requests and obtain results. Sending the results back is optional. |
|Bad case detection |Determine which samples are bad cases based on the evaluation score and confidence, and label them on the console page. |
|Prompt generation |Generate a prompt based on `task_description`. |


<span id="f8b1b65d"></span>
## Advantages

Guided by design principles of ease of use, modularity, extensibility, and openness, we strive to ensure:


* Low intrusion (ease of use): Modify only a few lines in existing agent or workflow code to implement the features listed in this document. Integration is simple.

* Modularity: Use modules individually or in any combination, such as evaluation, backflow, feedback, and prompt optimization.

* Extensibility and openness: Support multiple AI models, APIs, and multimodal data; seamlessly support open\-source frameworks such as LiteLLM, LangChain, and LlamaIndex for LLM or agent application development; and make it easy to extend use cases using existing capabilities.


<span id="00693238"></span>
## Core concepts

**Tasks and versions (task and version)**  :

The diagram below shows the mapping between the PromptPilot Console and the SDK. A task is typically created under a personal or team workspace, and it usually contains multiple prompt versions. Each version centers on a prompt and includes related version information, such as `task_id`, `version`, `prompt`, a variable list, evaluation criteria (`criteria`), the model name, and configurations such as `temperature` and `top_p`.

To stream data back via the SDK, users typically include `workspace_id` (to specify a workspace), `task_id`, `version`, `AGENTPILOT_API_KEY` (authentication for the ingestion service), and `ARK_API_KEY` (model inference on ModelArk) in the request. This covers most operations.

**Ingestion event (run)**  :

If a model call is sampled, it produces one ingestion event. Each ingestion event corresponds to one row on the platform's Batch page.

<span id="cb6ec355"></span>
# Precautions


* **Ingestion sampling rate** : The default sampling rate is 0.1, meaning each record has a 0.1 probability of being ingested. You can adjust it as needed.

* **Ingestion data cap** : The default is 2,000 records. If the number of records under a given `task_id` and `version` exceeds 2,000, ingestion fails and the SDK call returns a log message. This limit aligns with the console page. To increase the limit, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

* **Only the scoring mode for text understanding and visual understanding tasks is currently supported.**  If you need support for more task types, such as multi\-turn conversations and Tools, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

* **`model_name`** ** is the model name plus version and must be a model supported in the model dropdown on the Prompt Generation page.**  If you need support for custom or third\-party endpoints, submit a [Ticket](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00001514).

### How do I automatically report data?

Call `ap.render()` to render `task_id`, `version`, and variables, obtain the rendered `input_dict`, and pass it to the Ark client when calling the completion API. The system automatically retrieves the corresponding prompt version, assembles it into the input of the LLM inference request, and obtains the model answer. The completion API for LLM requests is compatible with the Ark client.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os

# Create client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render input for the inference request
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    api_key=None,
    api_url=None,
)

# Call Model inference, as with the ModelArk SDK
completion = client.chat.completions.create(model='seed-1.6-250615', **input_dict)

# Optional step: flush pending event messages in the queue and send them immediately. If you don't flush, the system automatically backfills in small scheduled batches to improve performance
ap.flush()

# Print the completion result
print(completion.choices[0].message)

# Print the event run_id, which corresponds to a row on the Batch page and is used for subsequent tracking, editing, and overwriting data
print(completion.run.id)
```

### How do I manually write back data?

In addition to automatically writing back data via the completion API, the SDK also lets you write back data manually. You can also override data after the automatic write\-back, such as adding an ideal answer (reference) or updating variables.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os
import time
import uuid

# Create a run_id or obtain the run_id of a backfill event from the above completion API response
run_id = str(uuid.uuid4())
task_id = "ta-20250101000000-aaaaa"
version = "v1"

# Backfill or overwrite the row of data corresponding to a run_id
ap.track_event(
    run_type="llm",
    event_name="reference",  # Backfill event name; any name is acceptable

    task_id=task_id,

    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    input_messages=[{"role": "user", "content": "This is a model input"}],
    output_message={"role": "user", "content": "This is a model output"},
    reference="This is a reference answer",
    api_key=None,
    api_url=None,
)
ap.flush()
```

### How do I provide human feedback scores?

After applying the patch, the Ark client is almost identical to the standard Ark completion API, except that the inference return value `completion` carries a write\-back event (`run`) as the unique identifier (`run.id`) for subsequent tracking (`track`) of a data record. As long as you have this identifier, you can append follow\-up actions, such as adding human scores and AI scores.

Continue from the code above: call the `ap.track_feedback()` API and pass a feedback dict. Provide human scoring data through the `human_score`, `human_analysis`, and `human_confidence` fields. After ingestion, log in to the console to view the record mentioned above; it now includes the score and scoring reason. This feature aligns with the console's manual scoring feature.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os

# Create the client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render the inference request input
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    api_key=None,
    api_url=None,
)

# Call Model inference, same as the ModelArk SDK
completion = client.chat.completions.create(model='seed-1.6-250615', **input_dict)

# Optional step: flush pending event messages in the queue and send them immediately. If you don't flush, the system automatically flushes small batches on a schedule to improve performance
ap.flush()

# Print completion results
print(completion.choices[0].message)

# Print the event run_id, which corresponds to a row on the Batch page and can be used for subsequent tracking, editing, or overwriting data
print(completion.run.id)

# Get the unique identifier run.id of the above event run
run = completion.run
if run is not None:
    print(run.task_id)
    print(run.version)
    print(run.id)

# Track and add human feedback scores
ap.track_feedback(
    task_id=run.task_id,
    version=run.version,
    run_id=run.id,
    feedback={
        "human_score": 5,
        "human_analysis": "The reason for manual scoring of this data",
        "human_confidence": 1.0,
    },
)

ap.flush()
```


If it runs successfully, log in to the Batch page under this task in PromptPilot; you will see that the ingested data now includes the score and scoring reason.

## 3. Online evaluation

<span id="03d5573c"></span>
### How do I submit an online evaluation request?

Call the `ap.eval.evaluate()` API. Enter an example and a metric, both dicts, and provide the relevant fields.

```Python
import agent_pilot as ap

# Samples to evaluate
example = {
    "prompt": "This is a prompt template, it contains {{variable_1}} and {{variable_2}}",
    "variables": {
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
    "response": "Content of model response",
}

# Scoring criteria
metric = {
    "criteria": "The text is fluent and logically clear. Obtaining 5 points if the response content is sufficient and there are no obvious omissions; otherwise, output the number 1."
}

# Run evaluation
result = ap.eval.evaluate(
    example=example,
    metric=metric,
    api_key=None,
    api_url=None,
)
print(result)
```


If successful, you will see the following output.

```Bash
example_id=None
reference=None
score=1
analysis="The task question did not clearly specify the requirements. The model's response did not reflect the processing of the content of variable 1 and variable 2. The response content was insufficient and there were obvious omissions, failing to meet the requirement in the evaluation criteria that the response content should be sufficient and have no obvious omissions. Therefore, the score is 1."
confidence=0.9
```


Specifically, we provide the following optional parameters:


* `example_id`: Users can specify this ID to map each sample to its evaluation result one\-to\-one, making lookup easier.

* `reference`: If the scoring criteria (`criteria`) requires comparing the model answer with a reference answer, use this field to pass the sample's reference answer. For example, `criteria`: "The model answer matches the reference answer."

   ```Python
   import agent_pilot as ap
   
   # Samples to evaluate
   example = {
       "example_id": "ex_id_1",                  # Optional
       "prompt": "This is a prompt template, which contains {{variable_1}} and {{variable_2}}",
       "variables": {
           "variable_1": "Content of variable 1",
           "variable_2": "Content of variable 2",
       },
       "response": "Model response content",
       "reference": "Reference answer content",               # Optional
   }
   
   # Scoring criteria
   metric = {
       "criteria": "The model's response is consistent with the reference answer, score 5, output the number 5. Otherwise, output the number 1."
   }
   
   # Invoke evaluation
   result = ap.eval.evaluate(
       example=example,
       metric=metric,
       api_key=None,
       api_url=None,
   )
   print(result)
   ```
   


If successful, you will see the following output.

```Bash
example_id='ex_id_1'
reference='Reference answer content'
score=1
analysis='The content of the model\'s response is inconsistent with the reference answer. According to the evaluation criteria, it should get a score of 1.'
confidence=1.0
```


In addition, for users' convenience, we also support the following two ways to build samples.


* Enter via the `messages` field, aligned with the Ark client's `messages` field API.

* Enter via the `input` field to ask the LLM directly.


```Python
import agent_pilot as ap


# Scoring criteria
metric = {
    "criteria": "The text is fluent and logically clear. If the response content is sufficient and there are no obvious omissions, score 5 and output the number 5. Otherwise, output the number 1."
}

# Enter directly via the messages field to align with the Ark client's messages field API
example = {
    "messages": [
        {"role": "system", "content": "You are a polite and friendly ordering robot, helping users place orders."},
        {"role": "user", "content": "How spicy is your boiled fish?"},
        {"role": "assistant", "content": "Hello, you can choose mild, medium, or spicy."},
        {"role": "user", "content": "Please give me a mild one."},
    ],
    "response": "Okay, a mild spicy boiled fish, I've placed your order for you, please wait a moment."
}

# Invoke evaluation
result = ap.eval.evaluate(
    example=example,
    metric=metric,
    api_key=None,
    api_url=None,
)
print(result)

# Enter via the input field to ask the model directly
example = {
    "input": "This is a prompt template, it has the content of variable 1 and variable 2",
    "response": "Model response content"
}

# Invoke evaluation
result = ap.eval.evaluate(
    example=example,
    metric=metric,
    api_key=None,
    api_url=None
)
print(result)
```

### How do I feed back the AI score?

The process is the same as feeding back human scores: track the event using the unique identifier (`run.id`) of the feedback event (`run`), then call the `ap.track_feedback()` API and pass feedback to add the AI score.

Unlike human scores, the AI score requires passing the `human_score`, `human_analysis`, and `human_confidence` fields as feedback. After feedback is sent, log in to the console page to see that the sample corresponding to `run.id` has updated its score and scoring reason, and the label "AI Score" is displayed next to it. This feature aligns with the intelligent scoring feature on the console page.

```Python
import agent_pilot as ap
from byteplussdkarkruntime import Ark
import os
import time

# Create client
client = Ark(api_key=os.getenv('ARK_API_KEY'))
ap.probing(object=client, sample_rate=1.0)

# Render the inference request input
input_dict = ap.render(
    task_id="ta-20250101000000-aaaaa",
    version="v1",
    variables={
        "variable_1": "Content of variable 1",
        "variable_2": "Content of variable 2",
    },
)

# Invoke Model inference, same as with the ModelArk SDK
completion = client.chat.completions.create(model='1.5-pro-32k-250115', **input_dict)
print(completion.choices[0].message)

run = completion.run

if run is not None:
    result = ap.eval.evaluate(
        example={
            "example_id": "example_id_1",
            "input": input_dict["messages"][0]["content"][0]["text"],
            "response": completion.choices[0].message.content,
        },
        metric={
            "criteria": "The text is fluent and logically clear. If the response content is sufficient and there are no obvious omissions, score 5 and output the number 5. Otherwise, output the number 1."
        },
        api_key=None,
        api_url=None,
    )
    print(result)

    ap.track_feedback(
        task_id=run.task_id,
        version=run.version,
        run_id=run.id,
        feedback={
            "metric_score": result.score,
            "metric_analysis": result.analysis,
            "metric_confidence": result.confidence,
        },
    )

    ap.flush()
```


If the run succeeds, log in to PromptPilot and go to the Batch page for this task. You will see that the returned data includes the score and scoring reason, and the score is labeled "AI Score".

### How do I generate scoring criteria?

Call the `ap.eval.generate_criteria()` API to generate scoring criteria by passing a sample list `examples`, where each element of `examples` is an example dict. This feature aligns with scoring criteria generation in intelligent scoring.

Specifically, each sample in the list can include `score` and `analysis` (scoring reason). When generating scoring criteria, the system does not distinguish between human scores and AI scores.

```Python
import agent_pilot as ap

# Sample list

    {
        "prompt": "This is a prompt template, it contains {{variable_1}} and {{variable_2}}",
        "variables": {
            "variable_1": "Content of variable 1 in sample 1",
            "variable_2": "Content of variable 2 in sample 1",
        },
        "response": "Model response 1",
        "reference": "Reference answer 1",            # Optional
        "score": 5,                         # Optional
        "analysis": "Scoring reason 1",             # Optional
    },
    {
        "prompt": "This is a prompt template, it contains {{variable_1}} and {{variable_2}}",
        "variables": {
            "variable_1": "Content of variable 1 in sample 2",
            "variable_2": "Content of variable 2 in sample 2",
        },
        "response": "Model response 2",
        "reference": "Reference answer 2",            # Optional
        "score": 1,                         # Optional

### How do I submit a prompt optimization task?

Call the `ap.optimize.create()` API, pass `task_id`, and specify `base_version`. The system creates an optimization job and associates an `OptimizeJob` object, `opt_job`. The object includes `job_id`, which serves as the optimization job's unique identifier.

```Python
import agent_pilot as ap
import time

# Call ap.optimize.create() to create an optimization job
opt_job = ap.optimize.create(task_id="ta-20250101000000-aaaaa", base_version="v1", api_key=None, api_url=None)

```

### How do I view optimization status and progress?

Using the `opt_job` object, call `opt_job.get_job_info()` to view the current optimization job information, including state and progress.


* When optimization finishes, `state` is one of `{ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED}`. If it is neither, wait briefly and query again.

* While optimization is running, `state` is one of `{ap.OptimizeState.CREATED, ap.OptimizeState.RUNNING}`.


Continuing from the code above, query the optimization job information every 5 seconds:

```Python
import agent_pilot as ap
import time

# Call ap.optimize.create() to create an optimization job
opt_job = ap.optimize.create(task_id="ta-20250101000000-aaaaa", base_version="v1", api_key=None, api_url=None)
print(opt_job)

# Query JobInfo via the opt_job object
job_info = opt_job.get_job_info()
while job_info.state not in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED}:
    # View the current state
    print(job_info.state)
    # View the current progress
    if job_info.progress is not None:
        print(job_info.progress.percent)         # Current optimization job completion percentage
        print(job_info.progress.optimal_prompt)  # Current optimal prompt
        print(job_info.optimized_version)

    # Re-fetch JobInfo after 5 seconds
    time.sleep(5)
    job_info = opt_job.get_job_info()

# After the optimization job completes, the status is SUCCESS or FAILED
print(job_info.state in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED})
```

### How do I obtain the optimization report?

If optimization succeeds, call the `opt_job.get_report()` API to obtain the optimization report.

```Python
import agent_pilot as ap
import time

# Call the API ap.optimize.create() to create an optimization job
opt_job = ap.optimize.create(task_id="ta-20250912125011-WDAtF", base_version="v1", api_key=None, api_url=None)
print(opt_job)

# Query JobInfo via the opt_job object
job_info = opt_job.get_job_info()
while job_info.state not in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED}:
    # View the current state
    print(job_info.state)
    # View current progress
    if job_info.progress is not None:
        print(job_info.progress.percent)         # Completion percentage of the current optimization job
        print(job_info.progress.optimal_prompt)  # Current best prompt
        print(job_info.optimized_version)

    # Retrieve JobInfo again after 5 seconds
    time.sleep(5)
    job_info = opt_job.get_job_info()

# After the optimization job ends, the status is SUCCESS or FAILED
print(job_info.state in {ap.OptimizeState.SUCCESS, ap.OptimizeState.FAILED})

if job_info.state == ap.OptimizeState.SUCCESS:
    report = opt_job.get_report()
    opt, base = report.opt, report.base

    # Compare prompts before and after optimization
    print(opt.prompt, base.prompt)

    # Compare metrics before and after optimization
    print(opt.metric, base.metric)

    # Compare average scores before and after optimization
    print(opt.avg_score, base.avg_score)

    # List data records before and after optimization
    print(opt.records, base.records)

## 5. Prompt generation

Call the `ap.generate_prompt_stream()` API, pass `task_description` and the model configuration, and generate the prompt as a stream. This capability aligns with the Prompt Generation page in the console.

The following example generates a prompt for a multi\-turn conversation task. To generate prompts for text understanding or visual understanding, set `task_type` to `"DEFAULT"` or `"MULTIMODAL"`, respectively.

```Python
import agent_pilot as ap

generated_prompt = ""
usage = None
print("Streaming response:")
for chunk in ap.generate_prompt_stream(
    task_description="I need a top-tier live streaming sales assistant; input is user's question, output is product introduction",
    task_type="DIALOG",
    model_name="seed-1-6-250615",
    temperature=1.0,
    top_p=0.7,
    api_key=None,
    api_url=None,
):
    # Handle streaming output
    generated_prompt += chunk.data.content
    print(chunk.data.content, end="", flush=True)
    if chunk.event == "usage":
        usage = chunk.data.usage

print(f"Generated prompt: {str(generated_prompt)}")
print(f"Usage: {usage}")
```

# Core Live Streaming Sales Strategies
## 1. Demand Anchoring Method
- First, quickly capture the potential needs in the user's question (e.g., if a user asks "What skincare product is not greasy in summer?", the need is "refreshing and oil-controlling"), and directly state it at the beginning of the answer: "Are you looking for a product that feels like water when applied, can keep your skin matte even with more oil in summer?"

## 2. Product Highlight Blasting
- Targeting the user's needs, extract 3 core highlights of the product, and use exaggerated but true effect descriptions like "3-second results", "amazing after use", "can't live without it" to strengthen memory points.

## 3. Creating Urgency and Scarcity
- Actively reveal hidden benefits': 'Now placing an order not only gets a 50-yuan discount, but the first 100 orders also include a free sample of the same product; only 3 sets of inventory left!'
