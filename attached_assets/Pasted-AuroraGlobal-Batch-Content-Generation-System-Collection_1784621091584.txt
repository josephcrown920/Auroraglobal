AuroraGlobal — Batch Content Generation System (Collection Runtime)

Objective

Implement a new execution model for the workflow builder that enables one source asset to generate many outputs while keeping the XYFlow canvas clean.

This is not a feature that creates 30 nodes.

Instead, implement a Collection runtime type that allows one node to internally process multiple execution jobs while appearing as a single node in the workflow.

The workflow editor should remain visually identical whether the user generates 5, 30, or 500 outputs.

⸻

High-Level Architecture

Separate the application into two systems.

1. Visual Workflow (XYFlow)

Responsible only for:

* Building workflows
* Connecting nodes
* Editing node settings
* Displaying execution state
* Never creating duplicate nodes

The canvas is a visual blueprint only.

⸻

2. Workflow Runtime Engine

Responsible for:

* Compiling the workflow
* Creating execution jobs
* Running workers
* Managing retries
* Parallel execution
* Queue management
* Progress reporting
* Collection iteration

The runtime must be completely independent from React Flow.

⸻

Collection Runtime

Implement a Collection model similar to:

interface Collection<T> {
  id: string;
  type: string;
  items: T[];
  status:
    | "queued"
    | "running"
    | "completed"
    | "failed";
  progress: number;
  completed: number;
  running: number;
  failed: number;
  metadata: Record<string, unknown>;
}

Collections must behave like arrays while preserving execution metadata.

⸻

Automatic Collection Processing

When a node receives Collection, the runtime should automatically execute the node once for every item.

Pseudo behavior:

if input is Collection
for each item
run node
collect outputs
return Collection

No manual iteration nodes.

No “For Each” node.

Iteration is automatic.
