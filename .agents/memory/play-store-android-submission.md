---
name: Play Store Android submission
description: How Aurora Studio ships to Google Play — sanctioned upload path and store-compliance requirements
---
- Manual Play Console AAB upload is the sanctioned path (per Replit's mobile-publishing docs). `eas submit` and service-account keys are explicitly OUT for Android — and every store doc (submission guide, listing readiness tables, rebuild notes) must stay consistent with that, or completion reviews bounce on the contradiction.
- Stash production AABs locally under the mobile artifact's `store/builds/` — EAS build download links expire (~30 days). Record sha256 + versionCode alongside, and bump `android.versionCode` for every upload.
- Consumption-only v1: strip ALL purchase/top-up copy from both the app AND the store listings (Play/Apple digital-goods rules). Credits language must describe spending/syncing, never buying.
- Account deletion for store compliance must delete from EVERY user-owned table explicitly — `auth.admin.deleteUser()` cascades only tables with an ON DELETE CASCADE auth FK, and most user tables have none. Storage purge failures must fail the request BEFORE any row deletes (a retry then sees an intact account). After auth deletion, a final storage+row sweep closes the race with in-flight work (claimed jobs write telemetry rows mid-request — observed live); if that sweep fails, queue a durable retry row drained by cron — the login is gone, so silent success would strand undeletable data.
- Every user-generated storage write must land under a uid-prefixed namespace. Anonymous `<feature>/<timestamp>` object paths are undiscoverable by account deletion (a store-compliance bug) — route uploads through the uid-prefixed helper/pattern, and auth-gate every upload endpoint (an unauthenticated service-role upload route is also an open storage-consumption hole).
- Play production ALSO requires a public WEB deletion page usable without reinstalling the app; in-app deletion alone passes internal testing only. Retained post-deletion: payments + legal_acceptances only, and the privacy policy must say so.
