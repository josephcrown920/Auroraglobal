name: Play Store Android submission path
description: How Aurora Studio Android releases actually reach Google Play from Replit
---
- Replit's sanctioned Android path is a MANUAL Play Console upload of the AAB (docs: /build/mobile-upload-android → /build/mobile-internal-testing). The expo skill's "Google Play not supported on Replit" note is stale — live docs supersede it. EAS CLI commands remain forbidden either way; a service-account JSON + Play Developer API is optional automation for LATER releases, never a first-release requirement.
- **Why:** the repo's original submission-guide and task text prescribed `eas submit`, conflicting with the expo skill prohibition; fetching the live Replit docs settled the path (manual upload) and de-scoped the service-account key.
- **How to apply:** for any Android release, hand the user the runbook (account → app record → download .aab from file tree → Testing → Internal testing → upload → testers/opt-in link); only reach for the Play Developer API if the user explicitly wants automated submissions, with the key requested via the secrets flow — never pasted in chat.
- EAS build artifacts expire ~30 days after the build finishes. If submission waits on user-side steps (e.g. Play account ID verification, ~48h), IMMEDIATELY download the AAB into gitignored `store/builds/` with a recorded sha256 so the artifact outlives the link. (Done 2026-08-15 for build `1c5efc61`, whose link expired 2026-08-20.)
- Play payments policy: never declare in-app purchases or point to off-Play checkout for digital credits anywhere in the Android app OR its store listing/description. v1 declares Free / no IAP; the app's web-billing links must be stripped (or replaced with Play Billing) before a production-track review — internal testing is lenient, production is not. (Owner decided 2026-08-15: strip for v1, Play Billing later; balance/history stay visible.)
- Account deletion: `auth.admin.deleteUser()` does NOT clean the legacy core tables (profiles/generations/credit_ledger have no auth FK) — the public account-delete endpoint deletes them explicitly, then storage, then the auth user. Play's deletion policy ALSO requires a WEB deletion link (usable without reinstalling) before production — in-app alone passes internal testing only.
