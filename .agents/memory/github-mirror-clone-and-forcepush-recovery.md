- **Fresh clones fail via LFS.** The repo's LFS storage is over quota → smudge fails → `gh repo clone` / checkout dies (exit 128) leaving a half-written index that later surfaces as thousands of phantom `D ` entries + "untracked working tree files would be overwritten ... Aborting" on any checkout. Repair: `GIT_LFS_SKIP_SMUDGE=1`, set `filter.lfs.smudge "git-lfs smudge --skip -- %f"`, `filter.lfs.process "git-lfs filter-process --skip"`, `filter.lfs.required false`, then `git reset --hard <ref> && git clean -fdq`. Keep `GIT_LFS_SKIP_SMUDGE=1` exported for all later git ops in that clone.
- **Push auth in scratch clones:** no credential helper by default ("Invalid username or token"); fix with `git config credential.helper '!gh auth git-credential'` — gh already holds GITHUB_TOKEN.
- **Ruleset "Protect head" (active):** blocks branch DELETION on existing branches (push --delete → "repository rule violations"). Creating new branches, fast-forward updates, and PR creation all pass. To update a stale protected branch, build a lineage that fast-forwards from its current tip: checkout the remote tip, `git merge origin/Main`, cherry-pick new work on top, plain push.
- **Force-push recurrence** (2026-08-26 ~16:34Z; prior incident 2026-07-29): a sibling commit force-replaced Main's tip and silently dropped a committed fix (Adult auth-loading UI, was 2f14321). **Why:** daemon/task-agent env clones can push non-descendant lineages over newer Main. **How to apply:** treat `(forced update)` lines in fetch output as an incident signal; immediately preserve the dropped commit via `git push origin <sha>:refs/heads/backup/<name>`; restore through a fast-forward branch + PR (PR #29 pattern) — never counter-force-push. Also: `gh repo fork` of your own repo fails; pre-clone instead when a script assumes fork.
