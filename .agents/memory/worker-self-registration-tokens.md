# GPU worker self-registration: two tokens, not one

A self-hosted worker (Colab/Kaggle notebook → `workers/aurora_worker.py`,
`workers/kaggle/aurora_worker_kaggle.py`, `workers/comfyui/aurora_comfyui_launcher.py`)
that auto-registers into `gpu_workers` on boot uses **two unrelated credentials**:

- `AURORA_REGISTER_SECRET` — a **private, operator-generated** secret (NOT the
  Supabase anon/publishable key). Sent as the `apikey` header to
  `POST /api/public/workers/register`. The register route rejects (503) if this
  env var isn't set server-side, and never falls back to the public anon key.
  This authenticates the worker *to Aurora*.
- `AURORA_WORKER_TOKEN` — the worker's **own `/generate` bearer** (optional). The
  worker enforces it on inbound generate calls, and forwards it in the register
  payload as `auth_token` so the dispatcher can authenticate *to the worker*.

**Why the register key had to stop being the public anon key:** the anon/publishable
key ships to every browser, so registration was effectively open — once image/video
jobs started routing to the self-hosted swarm first, anyone who knew the Aurora URL
could register a fake "worker" and receive real job inputs (including signed links to
private user media). The fix is a dedicated private secret, generated by the operator
and set identically in Aurora's env and in every worker launcher's secrets.

**Why the two tokens must not be merged:** an early task spec said to reuse
`AURORA_WORKER_TOKEN` as the register key, but that name already meant the /generate
bearer in `aurora_worker.py`. Collapsing them would either leak the worker's inbound
secret into the register header or break the existing /generate auth. Keep them
separate.

**How to apply:** when adding worker setup docs, notebook secrets cells, or new
worker endpoints, keep register/health auth on `AURORA_REGISTER_SECRET` (private,
apikey header) and keep the /generate bearer (`AURORA_WORKER_TOKEN`) independent.
`/api/public/workers/health` (cron-triggered probe of already-known workers, no new
capability grant) is intentionally still gated on the public anon key — only
*registration* (which grants swarm membership) needed the private secret. Five worker
env vars total: `NGROK_AUTHTOKEN`, `NGROK_STATIC_DOMAIN`, `AURORA_URL`,
`AURORA_REGISTER_SECRET` (required) and `AURORA_WORKER_TOKEN` (optional).
